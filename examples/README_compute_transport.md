# MMCE N 算力网络：方块、机器与线路职责

## 先区分三层

这套系统里有三种不同的对象，不要把它们当成同一类方块：

1. **MMCE 机器**
   - 供给机：产生 CU/t。
   - 消费机：使用 CU/t。
   - 研究终端：使用 CU/t 执行研究。
   - 算力矩阵：提供网络骨干和网络级吞吐限制。

2. **算力网络端点**
   - 放进 MMCE 机器结构中的端点，成型后自动归属该机器控制器。
   - 端点只负责声明“这台机器从哪里接入算力网络”。

3. **实体线路设备**
   - 算力线缆负责形成真实的线路。
   - 矩阵接入端口负责让线缆接入矩阵机器。
   - 分支交换节点负责把多条线路组织成可单独限制的分支。

## 一条完整算力路径

```text
供给机 / 消费机 / 研究终端
        |
        | 机器算力接口
        v
实体算力线缆，或无线覆盖
        |
        | 矩阵有线接入端口 / 矩阵无线接入端口
        v
分支交换节点（可选）
        |
        | 实体算力线缆
        v
矩阵核心端口
        |
        v
算力矩阵 MMCE 机器
```

这里的“矩阵核心端口”不是另一台机器，而是算力矩阵 MMCE 结构中的核心端点。
“分支交换节点”也不是第二个矩阵，更不会产生 CU/t。

## 方块职责表

| 注册名 | 玩家应当如何理解 | 放在哪里 | 是否必须 |
| --- | --- | --- | --- |
| `compute_port` | 机器算力接口：某台 MMCE 机器接入算力网络的位置 | 供给机、消费机、研究终端等 MMCE 结构内 | 所有需要算力的机器都需要 |
| `compute_cable` | 实体算力线路：证明两个端点确实连通 | 各端点之间 | 使用有线段时需要 |
| `wired_compute_interface` | 矩阵有线接入端口：线缆进入矩阵的入口 | 算力矩阵 MMCE 结构内 | 采用有线接入时需要 |
| `wireless_compute_interface` | 矩阵无线接入端口：提供机器侧无线覆盖 | 算力矩阵 MMCE 结构内 | 采用无线接入时需要 |
| `compute_distributor` | 分支交换节点：组织线路，并为一个分支提供独立限制 | 矩阵结构或独立分支结构内 | 只有需要分流或限制分支时需要 |
| `compute_matrix_port` | 矩阵核心端口：算力矩阵的网络骨干端点 | 算力矩阵 MMCE 结构内 | 每个算力矩阵结构都需要 |

## 有线接入端口等级

以下四个注册名是**同一个矩阵结构位置的替换件**，不是四种矩阵：

```text
wired_compute_interface              基础   96 CU/t
wired_compute_interface_reinforced   强化  192 CU/t
wired_compute_interface_advanced     高级  384 CU/t
wired_compute_interface_elite        极限  768 CU/t
```

它们只改变该有线接入口允许通过的物理 CU/t 上限，不改变矩阵机器的注册名，也不增加网络数量。

## 最小有线网络：不使用分支交换节点

只有一台机器、一台算力矩阵和一条线路时，直接连接：

```text
机器算力接口
    == 算力线缆 ==
矩阵有线接入端口
    == 算力线缆 ==
矩阵核心端口
```

这是默认搭法。此时不需要放 `compute_distributor`。

## 分支网络：什么时候才放分支交换节点

分支交换节点相当于算力网络里的交换机。它的意义不是“让网络能够运行”，而是把线路分组，方便单独管理：

```text
区域 A 的机器 -- 有线接入端口 --\
区域 B 的机器 -- 有线接入端口 ----> 分支交换节点
区域 C 的机器 -- 有线接入端口 --/          |
                                           | 算力线缆
                                           v
                                      矩阵核心端口
```

使用它的理由：

- 为某个区域或机器组设置独立的 CU/t 上限。
- 限制一个分支允许接入的机器数量。
- 将多条线路汇总到一条矩阵骨干。
- 把不同功能区的线路分开，便于排查故障。

重要规则：

- 线缆只是经过分支交换节点旁边，不会自动使用它的限制。
- 只有逻辑路由明确绑定到该节点的机器，才会受到该节点限制。
- 如果不需要分支限制，机器可以直接接入矩阵，不需要该方块。

## 无线接入：只省掉机器侧这一段线缆

无线接入端口不是“全网无线化”。它只替代机器到矩阵接入端口之间的那一段：

```text
机器算力接口
       ))) 无线覆盖 )))
矩阵无线接入端口
       == 算力线缆 ==
矩阵核心端口，或分支交换节点再到矩阵核心端口
```

所以无线接入端口仍然必须通过实体算力线缆连接到矩阵骨干。
它的作用是减少机器区域的布线，而不是取消矩阵侧的实体骨干。

## 实际吞吐量

机器最终能获得的 CU/t 取所有限制中的最小值：

```text
实际可用 CU/t =
min(
    供给机实际输出,
    算力矩阵网络吞吐,
    分支交换节点吞吐（使用时）,
    矩阵有线接入端口物理上限（使用有线时）,
    CraftTweaker 线路配置
)
```

如果研究或机器需求大于最终获得的完整 CU/t，则按当前规则不推进该研究或配方。

## 成型与绑定顺序

1. 成型算力矩阵 MMCE 结构，并确认结构中有 `compute_matrix_port`。
2. 使用 MMCE N 网络绑定器，把矩阵控制器加入目标网络。
3. 成型供给机、消费机或研究终端。
4. 确认这些机器结构内的 `compute_port` 已自动归属各自控制器。
5. 根据需求选择矩阵有线接入端口或矩阵无线接入端口。
6. 使用实体算力线缆连接矩阵侧骨干。
7. 只有需要分流或分支限制时，才加入 `compute_distributor`。
8. 在 CraftTweaker 中配置逻辑线路和路由。
9. 物理线路与逻辑路由都有效后，机器才会获得算力。

## 一句话判断

- 让机器拥有算力网络接口：在机器结构里放 `compute_port`。
- 让线缆接入矩阵：在矩阵结构里放 `wired_compute_interface`。
- 让机器无线接入：在矩阵结构里放 `wireless_compute_interface`。
- 让多个区域成为独立受限分支：放 `compute_distributor`。
- 让矩阵拥有网络骨干端点：在矩阵结构里放 `compute_matrix_port`。
- 只有一台机器和一条线路：不要放 `compute_distributor`。
