# MMCE N 实体算力传输联调

## 先记住一条规则

算力网络有两层：

- **物理层**：世界里真正放置的线缆和端点方块，决定线路有没有接通。
- **逻辑层**：CraftTweaker 中配置的线路名称、吞吐量和机器数量限制，决定接通后能分配多少算力。

例如，`work_line` 只是逻辑层的线路名称，不是一个必须寻找或放置的方块。它可以对应一组实际的有线接入端和算力线缆。

## 玩家需要认识的方块

| 名称 | 玩家理解 | 是否需要单独放置 |
| --- | --- | --- |
| 算力矩阵 | 算力网络的核心，提供全网吞吐上限 | 不需要单独放置；由矩阵结构内部的端口代表 |
| 分发节点 | 可选的交换节点，把一条骨干分成多个分支，并限制该分支 | 需要分支时才放置，直连时不需要 |
| 有线接入端 | 把实体算力线缆接入某条逻辑线路 | 需要使用有线传输时放置 |
| 无线接入端 | 在覆盖范围内接收机器的无线算力 | 需要使用无线传输时放置 |
| 机器算力端口 | MMCE 机器结构内部的算力出入口 | 放入每台需要算力的 MMCE 机器结构 |
| 算力线缆 | 形成真实的实体线路 | 连接所有有线骨干 |

**重要：**矩阵机器结构内部可能同时包含算力矩阵、分发节点、有线接入端和无线接入端。它们是同一个 MMCE 结构的不同功能端口，不代表需要额外成型四台机器。

## 三种连接方式

### 1. 有线直连

小型网络可以不使用分发节点：

```text
MMCE 机器
  └─ 机器算力端口
       └─ 算力线缆
            └─ 有线接入端
                 └─ 算力线缆
                      └─ 算力矩阵
```

这条路线只有一个有线接入端和一段回到矩阵的实体骨干。

### 2. 有线分支

需要把多个区域或多组机器分开管理时，在接入端和矩阵之间加入分发节点：

```text
机器 A ─ 算力线缆 ─ 有线接入端 ─┐
机器 B ─ 算力线缆 ─ 有线接入端 ─┼─ 分发节点 ─ 算力线缆 ─ 算力矩阵
机器 C ─ 算力线缆 ─ 有线接入端 ─┘
```

分发节点不是算力来源，也不是 MMCE N 网络控制器。它是被逻辑线路选中的交换/
分流点，只要机器端口、接入端、分发节点和矩阵之间均存在实体连通，就会对该
逻辑线路施加吞吐和机器数量限制；实体线缆允许存在冗余或环路：

1. 分支吞吐限制。
2. 分支机器数量限制。
3. 分支线路的物理隔离和故障定位。

分发节点可以理解为算力网络里的交换机。它不要求成为实体线缆图中的唯一必经
方块；线路的逻辑绑定决定哪一个分发节点的限制作用于该机器。

### 3. 无线接入

无线只替换“机器到接入端”的这一段：

```text
MMCE 机器
  └─ 机器算力端口 ))) 无线覆盖 ))) 无线接入端
                                      └─ 算力线缆
                                           └─ 分发节点（可选）
                                                └─ 算力矩阵
```

无线接入端本身仍然需要用实体算力线缆连接到矩阵或分发节点。无线不是全网无线化，而是减少机器到接入端之间的布线。

## “一堆接口”分别是什么

在矩阵结构中看到多个端口时，按下面的方式理解：

| 看到的内部端口 | 实际职责 |
| --- | --- |
| `compute_matrix_port` | 矩阵结构的网络根端口，代表算力矩阵 |
| `compute_distributor` | 矩阵结构或分支结构中的可选交换节点 |
| `wired_compute_interface` | 有线机器接入实体线路的位置 |
| `wireless_compute_interface` | 无线机器接入覆盖的位置 |
| `compute_port` | 普通 MMCE 机器内部的算力端口 |

这些是**端口角色**，不是五套互相独立的网络。正常使用时，玩家只需要决定“机器采用有线还是无线”“是否需要分支限制”。

## 自动归属

1. 用 MMCE 网络绑定器把矩阵控制器加入目标 MMCE N 网络。
2. 成型矩阵结构。矩阵结构内的端口会自动归属矩阵控制器。
3. 成型算力机器。机器结构内的机器算力端口会自动归属该机器控制器。
4. 用实体算力线缆连接需要有线连接的端点。
5. 右键任意算力端点，查看它的角色、自动归属控制器和 MMCE N 网络状态。

自动归属读取 MMCE 已成型结构的实际方块坐标，不会根据附近控制器猜测。控制器切换网络后，端点会同步到新网络；结构失效、控制器卸载或解绑网络后，自动归属会解除。

算力端点绑定器不再是正常机器搭建流程的必需品，仅保留给结构外独立端点和调试场景。结构内端点始终以当前 MMCE 结构控制器为准。

端点和线缆不会强制加载区块。线路所在区块卸载、控制器结构失效、端点失效或关键线缆被拆除后，对应算力路由停止工作。

## 逻辑配置如何对应物理线路

配置中的线路名称只负责描述一组能力：

```text
work_line
  吞吐量：96 CU/t
  机器上限：8
  无线：否
```

物理线路负责证明机器确实连接到了矩阵：

```text
机器算力端口
  -> 算力线缆
  -> 有线接入端
  -> 分发节点（如果配置指定）
  -> 算力线缆
  -> 算力矩阵
```

只有逻辑配置和物理线路都满足时，机器才能获得算力。配置中的 `interfaceId` 在玩家文档中统一称为“线路名称”，不要求与方块注册名相同。

## 路由状态

- `valid`：实体线路完整，且逻辑配置有效。
- `machine_endpoint_missing`：机器控制器没有已绑定的机器算力端口。
- `interface_endpoint_missing`：矩阵控制器没有对应类型的接入端。
- `distributor_endpoint_missing`：配置要求分发节点，但矩阵控制器没有对应节点。
- `matrix_endpoint_missing`：矩阵控制器没有算力矩阵端口。
- `wired_path_invalid`：有线链路不完整或被拆断。
- `wireless_backbone_invalid`：无线接入端到矩阵或分发节点的实体骨干不完整。
- `out_of_range`：机器控制器不在无线接入端的覆盖范围内。

单次路径搜索默认最多访问 8192 个已加载的线缆或端点方块，可通过 `mmcenetworks.cfg` 中的 `computeCableMaxVisitedNodes` 调整。
